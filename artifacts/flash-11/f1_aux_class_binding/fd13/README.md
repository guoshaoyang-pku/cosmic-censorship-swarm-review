## Finding (corrects the rev19 status note)

A WCC schema can assert **SCC content** (`AF-SCC-C2-VAC-GEN`: *the maximal development is
C²-inextendible*) inside an assertive path and still **pass** the frozen canonical gate.

Coverage is **not** the gap: rev19 already scans `non_vacuity.condition`
(`artifacts/formulation/tools/check_class_schema.py:71`, sha256 `000e09e4…`). The gap is the
**scope of the geodesic exemption**. Frozen code (line 312–314):

```python
if INEXTENDIB.search(s) and not GEODESIC.search(s):
    self.fail("R12", ...)
```

`s` is the **whole field value**. `non_vacuity.condition` legitimately opens with
“MGHD is future **geodesically** incomplete”; that single token sets `GEODESIC.search(s)`
true, so the exemption covers the entire (multi-sentence) field and the later sentence
*“The maximal development is C^2-inextendible.”* is never scanned for what it is.

The earlier rev19 status proposal (“add `non_vacuity.condition` to canonical R12 paths”,
`flash11-FORMDIFF02-rev19-status-20260912T0008`) is **superseded by this note**: the path was
already present.

## Caveats that must travel with this

1. **Format-dominated rejections.** Canonical rejects many non-canonical layouts at R01/R02
   before R12 is reached; corpus agreement is not semantic agreement. This finding is measured
   only on canonical-layout fixtures.
2. **FROZEN.json is stale.** The manifest still says revision 19 (`frozen_at` 00:04:48) while the
   authoring schemas changed afterwards. The binding here is to the tool (`000e09e4…`, still
   byte-matching) and `rule_spec.json` (`40f9bb9e…`, still byte-matching); the rev19 fixture uses
   the frozen corpus copy (`f962c117…`), and the rebase fixture uses the live schema
   (`b65fcc0f…`). Re-verify the tool hash before reusing this patch.
3. **Lexical, not semantic.** Even patched, R12 is a token scan. A leak phrased without
   `inextendib`/`extension`/`horizon` tokens still passes; worker-06 owns the rephrased corpus.
4. The patch was validated only through the copied patched tool; the proposal must be reviewed
   and applied by the schema owner, then re-run through `run_gate_tests.py`.
